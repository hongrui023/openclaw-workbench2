# 升级到 1.0.3（提速版）

> 2026-09-12

1.0.2 → 1.0.3 这次升级**只改行为，不改配置**：挂载、环境变量、端口全部不变。
镜像换 `openclaw-workbench:1.0.3`，重启容器就生效。

## 改了什么

| 项 | 之前 | 现在 |
|---|---|---|
| 文献分析同篇分块 | 串行（每块 30-60 秒） | 并发 2（环境变量可调 `LITERATURE_CONCURRENCY=3` 试一次） |
| 前端轮询间隔 | 写死 30 秒 | 任务刚启动 5 秒一次，跑过 60 秒改回 30 秒 |
| 反代下省流量 | 30 秒轮询不停 | 跑过 60 秒后大部分时间是 30 秒一次 |

**自检 110 → 118 项**（新增 8 项锁死新行为），其余三套全绿。

## 预期效果

| 场景 | 1.0.2 | 1.0.3 |
|---|---|---|
| 提交任务后看到首条进度 | 最长等 30 秒 | 5 秒内 |
| 16 页 PDF（3 块） | ~90 秒 | ~35-40 秒 |

## 下载镜像

镜像构建已成功（Actions run 34677883608）。

> 本机到 Azure Blob 下载速度约 4 MB/min（GitHub Actions artifact 存储限速），
> 用 GitHub 网页下载更快。

1. 打开 https://github.com/hongrui023/openclaw-workbench2/actions/runs/34677883608
2. 滚到底部 **Artifacts** → 点 `openclaw-workbench-arm64-1.0.3` 下载
3. 下载下来是 `.zip`，**解压一次得到 `.tar.gz`，再解压一次得到 `.tar`**
4. 落到本地路径，例如 `openclaw-workbench-1.0.3-arm64.tar`

## 导入并升级

1. 把 tar 上传到极空间任意文件夹（客户端 / 网页 / SMB 任意）
2. 极空间 → Docker → 镜像 → **导入镜像** → **从极空间导入** → 选 tar
3. 镜像列表里出现 `openclaw-workbench:1.0.3`
4. 容器 `workbench` → 先**停止** → **无损编辑**
5. 镜像下拉选 `openclaw-workbench:1.0.3`，**其他不动**
6. 保存 → 启动

启动后日志应该显示 `openclaw-workbench v1.0.2 启动中…`
（应用 `__version__` 仍是 1.0.2——这次没动它；镜像 tag 是 1.0.3。
下次发版会一起对齐，不影响使用。）

## 验证

跑一篇文献分析，看日志是否分块并发：第一次会立刻看到 "已完成 块1" / "已完成 块2" 几乎同时出现，而不是 1 → 2 → 3 串行。

跑完一篇后切到首页 / 切走再回来，过 60 秒轮询间隔应该自己变长（前端右下角不再显示"每 5 秒同步一次"，而是 "每 30 秒同步一次"）。

## 可能比代码改动效果更明显的两个运维自检

| # | 检查什么 | 怎么做 | 提速效果 |
|---|---|---|---|
| **F** | 节点小宝是不是中转模式 | 控制台 → 那条穿透 → 看"传输模式"或"状态" | 中转 = 2 Mbps 硬限制；改回 P2P = 不限速（可能 10-50x） |
| **G** | OpenClaw 的 default agent 是不是路由到 flash | 控制台 → Config → agents → default → model 字段 | 路由到 v3/R1 ≈ 5-10x 慢；改回 `deepseek/deepseek-v4-flash` 立刻生效（不重启工作台） |
