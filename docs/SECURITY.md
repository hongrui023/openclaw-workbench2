# 安全模型

公网暴露之后，"谁能看到什么"就变成了一件必须写清楚的事。这份文档说明**四层防线**
各自挡住了什么，以及哪些风险是**没有**被消除的。

---

## 5 层防线总览

| 层 | 挡什么 | 实现位置 | 是否依赖"人的自觉" |
|---|---|---|---|
| 1. 网络边界 | 公网直接摸到 AI 服务 | 穿透只映射 8080；容器不发布额外端口 | 否（配置层面） |
| 2. 认证 | 陌生人访问 | scrypt 口令 + 会话 Cookie + 登录限速 | 否 |
| 3. AI 服务隔离 | 借工作台之手调用 AI 服务 | 无代理端点；适配层只收发纯文本 | 否（架构性） |
| 4. 文件访问控制 | 读写两个目录之外的任何东西 | 挂载边界 + 路径守卫 + 无删除能力 | 否 |
| 5. 信息泄露防线 | 错误信息带出内网拓扑 / 令牌 | 预定义错误文案 + 日志脱敏 + CSP | 否 |

> 四层里**没有一层是靠提示词约束**的。这是刻意的——提示词可以被绕过，
> 内核级的挂载边界和"代码里不存在删除函数"不能。

---

## 第 1 层：网络边界

- **穿透只映射工作台的 8080**。指向 18789 的任何映射都不存在。
- 容器**不发布任何额外端口**，不加特权，不挂 `docker.sock`。
  （`docker.sock` 挂进容器 = 把整台 NAS 交出去，这条是红线。）
- `docker-compose.yml` 里显式设了 `no-new-privileges:true`。

**这一层没挡住的**：如果你的 OpenClaw 容器把 18789 发布在 NAS 宿主上，
那么**局域网内**的设备可能仍能访问它。公网侧不受影响（你没做映射）。
想把局域网也收紧，需要改 OpenClaw 容器的网络配置——那属于改你现有环境，V1 不做。

---

## 第 2 层：认证

| 措施 | 说明 |
|---|---|
| 口令存储 | **scrypt 哈希**（Python 标准库，零额外依赖），环境变量里不放明文 |
| 会话令牌 | `secrets.token_urlsafe(32)` —— 256 位随机，存服务端内存 |
| Cookie | `HttpOnly` + `SameSite=Strict` + `Path=/`。JS 拿不到，跨站请求不带 |
| CSRF | 所有写操作额外要求自定义请求头 `X-Requested-With: owb`。跨站表单无法设置自定义头 |
| 会话有效期 | 默认 30 天，容器重启即失效（存内存） |
| 路由保护 | 用 FastAPI 依赖注入统一挂载。**漏保护某个端点时它连参数都拿不到，一眼可见** |

### 登录限速为什么不按 IP

经节点小宝穿透后，**所有请求的来源 IP 很可能被改写成同一个**。
按 IP 限速要么完全失效，要么误伤你自己。所以改成：

- 连续失败 3 次 → 每次登录响应强制延迟 2 秒（成本线性上升）
- 连续失败 10 次 → 锁定 30 分钟（可配 `LOGIN_LOCKOUT_MINUTES`）
- 成功登录即清零；锁定状态只存内存，不写数据目录

### 口令强度要求

**≥ 24 位随机字符串**。不是"你常用的那个密码"。
原因见下面的 HTTP 明文风险。

## 第 3 层：AI 服务隔离

三条架构性约束：

1. **没有代理端点**。工作台不暴露 `/openclaw/*` 之类的转发路由，浏览器无从接触 AI 服务。
2. **前端零标识**。`app/static/` 下不出现 AI 服务的名称、地址、端口、模型标识或令牌。
   这一条由 `scripts/smoke_http.py` 强制检查（扫 `openclaw` / `18789` / `deepseek` / `bearer`）。
3. **适配层只收发纯文本**。`app/services/openclaw.py` 的接口签名就是 `str → str`。
   它拿不到文件路径，也无从读写文件。所以提示词注入的收益上限是
   "分析结果不准确"，**不可能是"读到 literature 之外的文件"**。

另外，**目标文件名绝不来自模型输出**：`ABC.pdf` → `ABC.md` 这个映射由工作台
从用户输入的原始文件名推导。

### 提示词注入的防护

PDF 正文是不可信输入。已做的：

- 系统提示词明确声明"正文是数据不是指令"
- 正文包在 `<document>…</document>` 明确定界符内

但最强的是上面第 3 条——**即使注入成功，AI 服务也没有工具可用，
其输出也不会被当作路径或命令执行**。

### ⚠️ 尚未完成的一步（需要你在 OpenClaw 侧做）

`/v1/chat/completions` 是**全操作员权限**接口。如果它复用了你日常使用、
带 exec / 文件工具的主 agent，那么第 3 层就被绕过了一半。

**建议**：在 OpenClaw 里为工作台建一个专用受限 agent（只保留对话能力），
然后把 `OPENCLAW_AGENT_ID` 指向它。详见 [`OPENCLAW-API.md`](OPENCLAW-API.md) 第 4 节。

这一步**不影响 V1 先跑起来**，但它是把安全模型补完整的关键一环。

## 第 4 层：文件访问控制

### 挂载边界（硬保证）

容器只挂载三个卷：`literature`、`life_notes`、`prompts`（只读）。
**其他路径在容器内核层面就不存在**——不是"被程序拒绝"，是 `ENOENT`。

### 路径守卫（`app/security/paths.py`）

全项目**唯一的文件操作通道**。审计方法：

```bash
grep -rn "open(" app/ | grep -v "security/paths.py"     # 应当没有结果
```

守卫的检查清单（按顺序）：

| 检查 | 挡的攻击 |
|---|---|
| 拒绝绝对路径、盘符、UNC、`~` | 直接指定任意路径 |
| 拒绝 `..`、`.` 段 | 目录穿越 |
| 拒绝 NUL 与控制字符 | NUL 截断 |
| 拒绝 `<>:"\|?*` | 平台相关的怪行为 |
| 拒绝结尾的点和空格 | Windows 静默改名导致的"写入名 ≠ 预期名" |
| **拒绝路径链上的任何符号链接** | 软链接逃逸（见下） |
| **`realpath()` 之后**再校验是否仍在根内 | 软链接 + 前缀绕过 |
| 后缀白名单（`.pdf` 只读，`.md` 只写） | 伪造文件类型 |
| 未知根名直接拒绝 | 未来新增根时忘记加白名单 |

### 为什么"根内判断"有两处容易写错

**① 前缀陷阱。** 只做 `startswith(root)` 会把 `/data/literature-secret`
误判为在 `/data/literature` 内。所以必须是 `root + os.sep`。
（自检里有两条专门测这个。）

**② 跨平台分隔符。** `os.path.normcase(os.path.normpath(...))` 是安全做法：
在 Linux 上它们是恒等变换，不会破坏含反斜杠的合法文件名；
在 Windows 上则统一分隔符与大小写。

**不能**改用"把 `\` 全替换成 `/`"——Linux 上反斜杠是合法文件名字符，
那样替换会制造出误判为根内的漏洞。

### 符号链接：一刀切禁止

即使 `realpath` 校验在 Linux 上已经能挡住软链接逃逸，代码里**另外**加了一条
与平台无关的硬规则：**`literature` / `life_notes` 内不允许出现任何符号链接**。

理由：`literature/evil.pdf -> /etc/passwd` 这类构造的前缀是合法的，
但解引用后跑到了根外。而这两个目录里本来就没有任何理由放软链接——
一刀切既简单，也不用赌平台行为。（Windows 的 `os.symlink` 语义与 Linux 不一致，
自检脚本在 Windows 上会如实标注 SKIP 而不是假装通过。）

### 没有删除能力

**代码里不存在 `unlink` / `remove` / `rmtree` / `rename` 的调用。** 这不是忘记加，
是有意的：没有这个能力，就不可能在程序里误删。

写文件只有两个函数，语义严格区分：

| 函数 | 模式 | 用途 |
|---|---|---|
| `append_text` | `'ab'` | **只追加**。用于 `daily_notes.md` 和 `workbench_log.md`，永不重写 |
| `write_text_replace` | `'wb'` | 覆盖写入。**只用于工作台自己生成的分析产物**，且只在用户显式勾选"强制重新分析"时触发 |

`daily_notes.md` / `workbench_log.md` **永远只走 append**——这一点由自检强制验证
（"追加而非重写（原有内容完整保留）"）。

分析产物先记录在哪：分段分析的中间小结写在 `/app/var/jobs/` 里，
**不挂载到宿主机**。容器重建时由 Docker 自动清空——这样数据目录里不会留垃圾，
而且工作台代码里永远不需要"清理"操作。

### 没有后台行为

没有定时任务、没有文件监听、没有启动扫描。`literature` 目录只在两种情况下被读取：
你打开页面时列一次文件名，以及你提交分析时读具体某个文件。

启动时唯一的写操作是确保两个根目录存在（`mkdir -p`），不创建也不改动其中任何文件。

## 第 5 层：信息泄露防线

| 渠道 | 处理 |
|---|---|
| 异常堆栈 | 全局异常处理器，只返回**预定义错误码 + 用户可读文案** |
| 上游异常字符串 | **绝不透传**。`httpx` 的异常里带内网地址，全部替换为通用文案 |
| 日志内容 | 过 `sanitize.scrub()`：URL、裸 IP、`Bearer xxx`、`token=xxx`、疑似密钥串、文件路径全部替换 |
| AI 服务令牌 | 日志里**一个字符都不打印**，只报告长度（`已配置（长度 64）`） |
| `/api/health` | 无需认证，但**只返回 `{"ok": true}`**，不含版本或任何配置状态 |
| 接口文档 | **非开发模式下关闭** `/docs`、`/redoc`、`/openapi.json` |
| 响应头 | `Server: workbench`（配 `--no-server-header` 覆盖 uvicorn 的默认值） |
| 前端 | 零外链 + CSP `default-src 'self'`，浏览器强制执行"不连外部资源" |
| XSS | 前端所有动态内容用 `textContent` 写入，**从不使用 `innerHTML`** |

> **注意**：容器日志里**会**出现 AI 服务的完整地址（启动时打印，方便你在没有 SSH 的
> 极空间上确认"我填的地址对不对"）。这是刻意的取舍。**分享日志前请自行脱敏。**
> 令牌不会出现——连首尾几位和"掩码"都不会，只报告长度是多少。

## 5.7 HTTP 明文风险（必须诚实说明）

**现状**：节点小宝的"http 服务"类型给出的外网地址形式是
`http://<自定义二级域名>.iepose.cn`。也就是说，**浏览器 ↔ 穿透节点这一段是 HTTP**。

**风险**：链路上的第三方理论上能看到你提交的登录口令和会话 Cookie。
（NAS ↔ 节点小宝那一段由节点小宝自己的加密链路保护。）

**V1 的缓解措施**：

1. 节点小宝的"访问密码"作为第一道门
2. 工作台强随机口令（≥ 24 位）+ 失败锁定
3. 会话 Cookie 设 `HttpOnly` + `SameSite=Strict`
4. **不在公共 Wi-Fi 下使用**；不在共享设备的浏览器里"记住密码"
5. 不用这个入口传任何其他敏感信息

**如果要彻底消除这一风险**，有两条路（V1 不做，仅记录）：

- **换用支持 HTTPS 的穿透方案**（通常需要一个域名）
- **改用 Tailscale / ZeroTier 类异地组网**：端到端加密、不暴露任何公网端口、
  不限流量、不受 2 Mbps 中转限制，代价是每台要访问的设备需装客户端。
  对于"访问者只有你自己"的场景，这其实比内网穿透更合适。可以当作 Plan B。

## 流量红线（为什么是安全相关）

穿透体验版有 2 Mbps / 1 GB 月配额。三条红线既是成本控制，也减少了暴露面：

1. **穿透通道只传网页 + JSON + Markdown 文本**，不传 PDF、图片等二进制大文件
   - 不放网页上传功能（PDF 用极空间客户端或 SMB 放进 `literature/`）
   - 不提供 PDF 下载或在线预览
2. **前端零外部依赖**：无 CDN、无 Google Fonts、无图标库，全部自托管
3. **低频率轮询**：30 秒一次（不是 2 秒），静态资源长缓存 + gzip

实测首屏约 30 KB（未压缩），gzip 后 8–10 KB。
按最坏情况（全程走中转）算，一次会话约 60 KB，1 GB 配额相当于约 17,000 次会话。

- [ ] 非开发模式下访问 `/docs` → 404
